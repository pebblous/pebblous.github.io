## LinkedIn (KO)

'나를 지워 달라'는 요청이 도착해도 지울 곳을 못 찾는 일이 벌어지기 시작했다.

2026년 들어 Claude Memory Tool, ChatGPT Memory 같은 도구가 실무에 들어오면서, AI 에이전트는 세션이 끝난 뒤에도 사용자에 대한 관찰을 파일에 스스로 적어 둔다. 문제는 그 기록에 "누구 것"이라는 이름표가 없다는 데 있다. 배포자는 저장소는 통제하지만, 그 안에 무엇이 누구 이름으로 쌓이는지는 모른다.

삭제는 대상을 특정하는 데서 시작한다. 이름표 없는 메모리에서는 그 첫 단계부터 막힌다. 삭제 버튼이 없어서가 아니라, 무엇을 눌러야 할지 아무도 모르는 것이 문제다.

다중 사용자 벤치마크 PiSAs에서는 메모리를 붙이자 노출 위반이 36~47%에서 63~90%로 뛰었다. 기억을 저장하는 그 기능이 유출면을 함께 넓힌 것이다. 해법은 사후에 붙이는 삭제 버튼이 아니라, 기록하는 순간에 이름표를 남기는 설계다. 프로버넌스가 없으면 삭제도 없다.

## LinkedIn (EN)

A "delete me" request can now arrive with nowhere to land.

Through 2026, tools like Claude Memory Tool and ChatGPT Memory have moved into real workflows, and AI agents now write observations about users into files that outlive the session. The catch is that those records carry no name tag. The deployer controls the storage but not what accrues inside it, or under whose name.

Deletion begins by identifying its target. With untagged memory, it stalls at that first step. The problem isn't a missing delete button; it's that no one knows which one to press.

In the multi-user benchmark PiSAs, adding memory pushed exposure violations from 36–47% to 63–90%. The very feature that stores a memory also widens the surface it can leak through. The fix isn't a better delete button bolted on afterward. It's a name tag written at the moment of recording. No provenance, no deletion.

## Facebook (KO)

어떤 앱에 "내 정보를 전부 지워 달라"고 요청해 보신 적 있으신가요?

그 버튼을 누르면 무언가 사라졌다고 믿습니다. 그런데 요즘 AI 에이전트에게는 그 믿음이 잘 성립하지 않습니다.

2026년의 에이전트는 대화가 끝난 뒤에도 나에 대한 관찰을 파일에 적어 둡니다. "이 사용자는 야근이 잦다", "배우자가 당뇨 관리 중" 같은 문장이 session-context.md 같은 이름의 파일에 조용히 쌓입니다. 제가 저장해 달라고 한 적도 없는데 말입니다.

문제는 그 파일 어디에도 "이건 누구 것"이라는 이름표가 없다는 데 있습니다. 저장소를 소유한 회사조차, 그 안의 어느 문장이 누구 것인지 알지 못합니다.

한 법률 매체는 이 상황을 한 문장으로 정리했습니다. "당신은 에이전트가 저장했다는 사실조차 모르는 것을 지울 수 없다."

그래서 자꾸 걸리는 것은 이 물음입니다. "이름표 없는 기억을, 우리는 대체 어떻게 지울까요?"

페블러스가 오래전부터 학습 데이터의 계보를 진단해 온 이유도 여기서 만납니다. 어디서 왔는지를 알아야 그 사람 몫만 정확히 지울 수 있으니까요. 이름표는 나중에 붙일 수 없습니다. 기록하는 그 순간에만 남길 수 있습니다.

그러니 다음에 어떤 메모리 기능을 켜든, 물어야 할 질문은 하나일지 모릅니다. 이 기억에는 이름표가 있는가.

## Facebook (EN)

Have you ever asked an app to erase everything it knows about you?

You press the button and trust that something disappeared. With today's AI agents, that trust no longer quite holds.

The agents of 2026 keep writing observations about us after the conversation ends. Lines like "this user works late often" or "their spouse is managing diabetes" settle quietly into a file with a name like session-context.md. No one asked for them to be saved.

The trouble is that nowhere in that file is there a name tag saying whose this is. Even the company that owns the storage can't tell which sentence belongs to whom.

A legal publication put it in a single line: you cannot delete what you do not know the agent stored.

So one question keeps catching. "A memory with no name tag — how would we ever erase it?"

This is where Pebblous meets a habit it has long practiced: diagnosing where training data came from. You can only remove one person's share once you know whose it is. And a name tag can't be added later; it can only be left at the moment of writing.

Whatever memory feature you switch on next, the question may come down to one thing. Does this memory carry a name?
