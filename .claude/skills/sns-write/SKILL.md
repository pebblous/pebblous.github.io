# sns-write v2 — 회사형 문안 두 칸 (2026-11-25)

블로그 글 하나를 링크드인과 페이스북에 알리는 짧은 기자 브리핑을 국문·영문으로 쓴다.
두 채널에 **같은 글**을 올린다. 트위터 문안, 페이스북 전용 에세이, 개인 계정용 1인칭 문안은 만들지 않는다.

좋은 문안은 피드에서 첫 줄만 보고도 무슨 일인지 알 수 있고, 출처를 대고, 데이터·AI 실무자에게 왜 중요한지 한두 문장으로 말한 뒤 링크로 넘긴다. 본문을 줄여 다시 쓰는 글이 아니다. 문안이 길어지는 가장 큰 원인은 본문 전체를 옆에 펴 놓고 쓰는 것이라서, 아래 순서대로 **요지 카드를 먼저 만들고 카드만 보고 쓴다.**

## 1. 읽는다

- 대상 글의 `ko/index.html` 과 `en/index.html` (본문만 — 다른 스킬·문체 지침을 따라가며 읽지 않는다)
- 이 파일의 `references/examples.md` — 형님 판정을 거친 예시 세 편. 목소리와 길이를 여기에 맞춘다

## 2. 요지 카드를 만든다

실행 디렉터리(run directory)가 있으면 `sns-write_card.md` 로 저장하고, 없으면 머릿속에만 둔다.

- **한 줄 요지** — 누가 무엇을 했나, 이름으로 (회사·기관·모델·법)
- **핵심 사실 2~3개** — 각각 출처(기관·매체·논문)와 날짜. 수치는 본문에 있는 그대로
- **왜 중요한가 1개** — 데이터·AI 를 다루는 실무자의 자리에서
- **전문이 짚은 쟁점 1개** — 본문의 해석 절이 실제로 내린 판단. 없으면 비운다
- **끝맺음 후보** — 아래 4절에서 이 글에 맞는 것 하나

## 3. 두 칸을 쓴다

뼈대 (KO·EN 같음):

1. **첫 줄** — 사실 한 문장. 주인공의 이름이 들어가고, '더보기' 전에 읽힌다 (KO 70자 안팎)
2. **무슨 일** — 2~4문장. 출처를 밝힌다 ("~가 발표했다", "로이터에 따르면", "arXiv 에 공개된 프리프린트(동료 심사 전)는")
3. **왜 중요한가** — 1~3문장
4. **끝맺음** — 한 문장 (4절)
5. `▶ 전문: <KO URL>` / `▶ Read: <EN URL>` 한 줄, 그 아래 해시태그 한 줄

- **한국어는 해라체**("~다"). 합쇼체·해요체를 쓰지 않는다
- **영어는 직역하지 않는다.** Reuters·FT 기사 첫머리처럼 영어 독자에게 다시 쓴다. 같은 사실을 쓰되 문장은 새로 짓는다
- **1인칭을 쓰지 않는다** (나·우리 / I·we·our). 회사 계정 목소리가 아니라 기자의 목소리다
- **페블러스는** 전문이 짚은 쟁점을 한 문장으로 옮길 때만 드러난다("전문은 이 사례를 ~로 짚었다"). 회사·제품 소개 문장은 쓰지 않는다

## 4. 끝맺음은 글마다 고른다

모든 글에 같은 꼴로 끝내지 않는다. 그 글에서 가장 자연스러운 것 하나를 고른다. 평서문일 수도 있고 질문일 수도 있다.

| 이 글이 남기는 것 | 끝맺음 예 |
|---|---|
| 독자가 당장 확인할 일 | "데이터를 다루는 팀이 지금 확인할 것은 하나다. 쓰는 모델과 데이터셋이 자체 저장소에 사본으로 있는가." |
| 수치를 잘못 읽기 쉬움 | "두 수치는 기간도 대상도 달라 합산해 읽을 값이 아니다." |
| 결과의 단서·한계 | "다만 바이두가 모델 카드에 적은 점수는 다른 판본의 시험이다." |
| 전문의 해석 | "전문은 이 사례를 AI 학습 데이터의 공급 주기 문제로 짚었다." |
| 아직 답이 없는 쟁점 | 열린 질문 한 문장 — 독자가 실제로 판단해야 하는 것일 때만 |

질문으로 끝낼 때는 "여러분 팀은 어느 쪽인가?"처럼 어느 글에나 붙는 질문을 쓰지 않는다. 그 글의 사실에서만 나오는 질문이어야 한다.

## 5. 쓰지 않는 것

- 회사 자기소개 문장 ("페블러스는 DataClinic 으로 … 진단한다", "Pebblous diagnoses …"), 제품 나열
- 비유와 꾸밈 ("품질표의 옆 칸", "저울이 달라졌다", "그 자로 재면")
- 해설·예고 문장 ("읽을 때 걸리는 자리가 있다", "떼어 둘 대목이 둘 있다", "다시 말해", "한 줄로 옮기면")
- "A가 아니라 B다" 대조 — 한 칸에 한 번까지
- 이모지, 볼드 소제목, 불릿
- 본문에 없는 수치·사실

## 6. 숫자로 정한 기준 — `tools/check-sns.py` 가 센다

| 항목 | 기준 |
|---|---|
| 본문 길이 (링크·해시태그 줄 뺀) | KO 350~600자 · EN 700~1,300자 |
| 수치 (금액·비율·건수·명수·점수) | 칸마다 3개 이하. 날짜·기간은 세지 않는다 |
| 해시태그 | 3~5개, 그중 하나는 `#페블러스` / `#Pebblous`. 나머지는 주제어 |
| 회사 자기소개 문형 | 0 |
| 1인칭 | 0 |
| "아니라" / "not … but" 대조 | 1 이하 |
| 수치의 출처 | 칸의 모든 수치가 같은 언어 본문에 있다 |
| 링크 | KO 칸은 `/ko/`, EN 칸은 `/en/` 전문 주소 |

## 7. 출력과 검사

경로: 글 폴더의 `sns/index.md` (예: `blog/<slug>/ko/index.html` → `blog/<slug>/sns/index.md`). 있으면 덮어쓴다.

```markdown
# SNS 홍보 글: {KO 제목}

> 소스: {blog path}
> 생성일: {YYYY-MM-DD}
> URL (KO): https://blog.pebblous.ai/{path}/ko/
> URL (EN): https://blog.pebblous.ai/{path}/en/
> 규격: sns-write v2 (회사형 · 링크드인·페이스북 공용)

---

## LinkedIn · Facebook (KO)

{KO 문안}

▶ 전문: https://blog.pebblous.ai/{path}/ko/
#… #페블러스

---

## LinkedIn · Facebook (EN)

{EN 문안}

▶ Read: https://blog.pebblous.ai/{path}/en/
#… #Pebblous
```

절 제목은 위 두 줄 그대로 쓴다 (콘솔이 KO 절을 찾아 맨 위에 보여 준다).

쓴 뒤 반드시 돌린다:

```bash
python3 tools/check-sns.py {blog-parent-dir}/sns/index.md
```

불합격 항목이 있으면 그 칸을 고치고 다시 돌린다. 통과할 때까지 끝내지 않는다. 마지막 검사 출력 줄을 결과에 그대로 남긴다.

## 8. 미디엄 (요청할 때만)

사용자가 미디엄 요약 기사를 명시해 요청하면 `references/medium.md` 를 따른다. 엔진 자동 단계에서는 만들지 않는다.
