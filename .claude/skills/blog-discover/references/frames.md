# 갈래별 글 틀

발굴 후보를 작성 단계로 넘길 때 그 갈래의 틀을 주제에 붙인다. 틀은 **빠뜨리면 안 되는 질문**이지 목차가 아니다. 문체·제목·형식은 글쓰기 스킬과 정본을 따른다.

## 공통 (시리즈 모든 갈래)
- 사이드카에 `series`(주제 id)·`seriesSlot`(갈래 id)을 남긴다. 주간·월간은 연재 이름(예: 주간 피지컬 AI)을 제목 앞머리에 밝힌다.
- 끝에 같은 주제 허브와 같은 연재의 이전 글 하나 이상으로 잇는다(실재하는 쪽만).
- 확인한 것과 저자 주장과 우리 해석을 구분해 적는다.

## 데이터 품질
- **DQ-2 논문**: 어떤 데이터 결함을 다루나 / 어떻게 재나(지표·데이터셋) / 고치면 다운스트림이 얼마나 달라지나 / ISO/IEC 5259-2 품질 특성 가운데 어디에 해당하나(대응이 해석이면 해석이라고 쓴다).
- **DQ-3 규제·표준**: 무엇이 언제부터 의무인가 / 누가 대상인가 / 데이터 쪽에서 무엇을 남겨야 하나(기록·검사·문서) / 확정과 초안을 구분.
- **DQ-4 새 데이터셋**: 규모·수집 방법·라벨 방식·라이선스·알려진 결함을 표 하나로 / 무엇을 학습하기 좋은가와 무엇에 쓰면 위험한가.

## 합성데이터
- **SD-1 연구**: 무엇을 만들었나 / 어떻게 검증했나 / 다운스트림에서 어느 조건이 움직였고 어느 조건이 안 움직였나 / 실측 데이터를 같은 양 더한 비교가 있나(없으면 없다고).
- **SD-2 산업**: 무슨 일(발표·투자·인수) / 무엇을 판다고 주장하나 / 검증된 성과와 주장을 구분.

## 피지컬 AI
- **PA-1 데이터셋**: 센서 구성·시간 동기·샘플링 주기·라벨·작업 수·규모·라이선스를 표 하나로 / 어떤 정책·모델 학습에 쓰였나.
- **PA-2 모델**: 입력과 출력(행동 표현) / 학습 데이터 / 어떤 시험에서 몇 점, 실물 시험이 있나.
- **PA-3 실험 사례**: 작업·조건별 성공률 표 / 시행 횟수 / 실패가 몰린 조건.

## AI 에이전트
- **AG-1 프레임워크**: 무엇이 새롭나 / 기존 도구와 무엇이 다르나 / 공개 범위(오픈소스·라이선스).
- **AG-2 방법론·성능 측정**: 성능 주장의 측정 조건(과제·시간·도구·채점) / 무엇이 실력이고 무엇이 측정 방식의 효과인가.
- **AG-3 AI 안전**: 무엇을 시험했나 / 결과와 한계 / 누가 평가했나(자체·외부).
- **AG-4 AI 규제**: 무엇이 언제부터 / 대상과 의무 / 집행 상태(확정·유예·소송).

## 주간 (금요일)
- 그 주 같은 주제 글 목록 + 다루지 못한 주요 소식 2~3개.
- 나열하지 않는다. "이번 주 이 주제에서 무엇이 바뀌었나" 하나의 이야기로 엮고, 각 항목은 원 글로 잇는다.

## 월간 (월말) — Pebblous Data Magazine
- 그달 주간 4~5호를 바탕으로 한 달을 읽기 쉬운 이야기로 다시 쓴다.
- 이달의 흐름 셋, 다음 달에 지켜볼 것 하나. 네 편을 잇는 호 표지 쪽을 함께 만든다.
