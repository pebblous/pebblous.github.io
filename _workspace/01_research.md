## 독자 페르소나
- 데이터 사이언티스트·ML 엔지니어 — "우리 회사 데이터가 모자라다"는 통념을 재검토 중인 의사결정자도 포함.
- fMRI/뉴로이미징 전문 지식은 없다고 가정. BIDS, fMRIPrep, 아틀라스, 파셀화 같은 용어는 본문에서 1회 풀어 쓴다.
- 기대: "새로 안 모으고 이미 있는 걸 다시 돌렸더니 대형 코호트급이 됐다"는 구체적 증거(수치·방법)와, 자사 데이터에 적용 가능한 교훈.

## 핵심 질문 (5개)
1. Open-fMIND는 정확히 무엇을 공개했나 — OpenNeuro 322건을 어떤 단일 규격(fMRIPrep 25.2.3)으로 다시 돌렸고, 그 결과물의 형태(시계열·연결성 행렬·52개 아틀라스)는 무엇인가.
2. "영국 바이오뱅크와 비슷한 하류 성능"이라는 저자 주장은 논문 어느 표·수치로 뒷받침되나 — 어디서 이기고 어디서 졌나.
3. 이 코퍼스는 어떻게 만들어졌나(수집 방법) — 1,066개 후보 → 387개 처리 → 322개 최종 릴리스로 좁혀진 과정, fMRIPrep 실패 2,637명 제외.
4. 라벨은 어떻게 매겨졌나(라벨 방식) — rest/task 구분, task_type_mapping.tsv, qc.tsv의 품질 지표. "라벨링"이 사실상 원 연구 메타데이터 상속이라는 점.
5. 무엇을 학습하기 좋고 무엇에 쓰면 위험한가 — 저자가 명시한 권장 용도(자기지도 사전학습, 아틀라스 멀티뷰 대조학습)와 경고(표현형 naive 병합 금지, 모집단 대표성 가정 금지, 라이선스 혼재).

## 아웃라인

### 섹션 1 (Executive Summary 직후, 도입): 공개된 것이 정확히 무엇인가
- OpenNeuro 322개 연구(참가자 11,379명·기능 영상 run 45,731개·약 6,044시간)를 fMRIPrep 25.2.3 단일 파이프라인으로 재전처리.
- 52개 아틀라스(14개 계열)로 파셀화한 시계열 약 238만 개(quasiraw 기준) + 기능적 연결성 행렬, 총 4.35TB(약 3GB 샤드 1,821개).
- 개별 OpenNeuro 데이터셋은 중앙값 25명 수준(WebSearch 요약) — 흩어진 소규모 연구를 묶어 단일 자원으로.

### 섹션 2: 수집 방법 — 1,066 → 387 → 322, 그리고 뭐가 빠졌나
- OpenNeuro GraphQL API로 인간 fMRI 데이터셋 1,066개 질의.
- 검수에서 27개 제외(BOLD run 없음 24, derivative 2, 명시적 제외 1) → 387개 처리 대상, 다운로드 실패 1개 추가 제외 → 359개(Table 3).
- 359 → 322로 줄어드는 과정은 논문 본문에 명시돼 있지 않음(확인 필요 → "확인한 것"과 "미기재"를 본문에서 구분해 적을 것). fMRIPrep 처리 실패 피험자 2,637명 제외는 명시됨.
- 스냅샷: 17개 데이터셋은 버전 기록이 없어 다운로드 시점 최신본으로 간주(불확실성 명시).

### 섹션 3: 라벨 방식과 품질관리 — "라벨"은 새로 붙인 게 아니라 상속
- task/rest 라벨 부여 방법 자체는 논문 본문에 상세 기술 없음 — task_type_mapping.tsv가 (데이터셋, task) 쌍마다 라벨 제공, BIDS task 엔티티를 그대로 사용(= 원 연구가 이미 붙인 라벨을 표준 스키마로 옮긴 것).
- qc.tsv: mean FD, max FD, 0.5mm 초과 볼륨 비율, 볼륨 수 등 BIDS 엔티티별 기록. **저자는 품질이나 움직임을 이유로 run을 제거하지 않았다** — 느슨한 FD 0.5mm 기준을 의도적으로 설정, 엄격한 기준이 필요한 사용자는 qc.tsv로 직접 필터링하라고 명시.
- preproc(디노이징 버전)에서는 scrubbing 후 50볼륨 미만 run 제외 → quasiraw(322, 45,731 run)와 preproc(320, run 수 적음, 712 run 차이) 수치가 다름 — 품질 기준에 따라 "같은 데이터셋"의 크기가 달라진다는 점이 품질 리터러시 포인트.

### 섹션 4: "영국 바이오뱅크와 비슷한 성능" — 표로 확인
수치 표 (논문 본문 직접 인용, 모델: Open-fMIND vs UK Biobank 각각 사전학습한 Brain-Semantoks, Gijsen et al. ICLR 2026):

| 데이터셋 | 과제(지표) | Open-fMIND | UK Biobank | 무작위 초기화 |
|---|---|---|---|---|
| HCP-YA | 일반 인지 요인 (Pearson r) | 0.415 | 0.409 | 0.380 |
| HCP-YA | 성별 (AUROC) | 0.945 | 0.945 | 0.877 |
| ABIDE | 진단 (balanced acc.) | 62.0% | 63.1% | 명시 없음 |
| ABIDE | 성별 (balanced acc.) | 62.8% | 65.7% | 명시 없음 |
| ABIDE | 연령 5등급 (balanced acc.) | 45.6% | 40.6% | 명시 없음 |
| ADHD-200 | 성별 (balanced acc.) | 67.2% | 70.0% | 명시 없음 |

- 저자 표현(직접 인용, 125자 이내로 옮길 것): "Open-fMIND 모델이 ABIDE 진단에서 UK Biobank 모델보다 약 1점 낮고, 성별에서 약 3점 낮고, ABIDE 연령에서는 5점 높다" / "성별(HCP-YA AUROC)에서는 UK Biobank 모델과 일치한다".
- **확인한 것**: 6개 지표 중 Open-fMIND가 2개(HCP 인지, ABIDE 연령)에서 UK Biobank를 앞섰고, 1개(HCP 성별)는 동률, 3개(ABIDE 진단·성별, ADHD-200 성별)는 뒤졌다 — "비슷한 성능"은 평균적으로는 맞지만 전 과제 우위는 아니다.
- **저자 주장 vs 우리 해석 구분**: 저자는 "게이트된 자원(UK Biobank) 수준에 근접한다"고 결론. 우리 해석: 공개 데이터만으로 비공개 대형 코호트에 필적한다는 것 자체가 사전학습 자원으로서는 의미 있는 결과이되, "동등"은 과장이고 "근접"이 정확한 표현.

### 섹션 5: 무엇을 학습하기 좋고, 무엇에 쓰면 위험한가
**좋은 용도** (저자 명시):
- 라벨 불필요한 자기지도 목적 — 마스크 재구성, 대조학습, 예측 사전학습.
- 52개 아틀라스를 한 run의 여러 "뷰"로 활용한 대조학습(단, 계열(family)을 먼저 뽑고 그 안에서 변형을 뽑아야 뷰가 고르게 분산).
- 지도학습이 필요하면 원 연구 메타데이터로 직접 타깃 구성 + provenance로 accession 추적.

**위험한 용도** (저자 경고, 직접 인용 또는 125자 이내 의역):
- 데이터셋 간 표현형을 "naively" 합치지 말 것 — 열 이름이 같아도 측정 도구·단위·코딩이 다를 수 있음.
- 아틀라스 멀티뷰는 같은 run의 결정론적 변환 — 독립 표본이 늘어난 것으로 착각 금지.
- 코퍼스가 특정 모집단을 대표한다고 가정 금지(성별 확인 69.4%: 여 38.3%·남 31.0%·제3범주 0.1%, 나이 확인 71.7%: 평균 28.7세·중앙값 24.0세로 젊은 성인 쪽 편중).
- 라이선스 혼재 — CC0 251, PDDL 34, not_stated 30(CC0로 취급), CC-BY-SA 3(파생물도 동일 라이선스 의무), CC-BY-NC 1(파생물 비상업 제한), CC-BY 2, 기타 1. 전체를 CC0처럼 쓰면 안 되고 LICENSES.tsv로 개별 확인 필요.
- 엄격한 움직임 기준이 필요한 분석에는 기본 전처리(느슨한 FD 0.5mm)를 그대로 쓰지 말고 qc.tsv로 재필터링.

### 섹션 6: 페블러스 관점 — "데이터가 모자란다"의 상당 부분은 "정리가 안 됐다"
- 사용자 제공 앵글 그대로 전개: 새로 찍은 영상 0장, 이미 공개된 322건을 같은 규격으로 다시 돌리고 출처를 파일 단위로 붙인 것만으로 대형 코호트급 사전학습 자원 확보.
- AI-Ready Data(수집이 아니라 규격·전처리·계보)의 수치적 사례로 연결 — "규격"=fMRIPrep 25.2.3 단일 버전, "전처리"=52아틀라스 파셀화+디노이징 선택지, "계보"=런별 provenance·accession·GeneratedBy 메타데이터.
- 독자에게 남기는 질문(사용자 제공 문구 활용): 이미 가진 데이터를 같은 규격으로 다시 돌리면, 새로 사는 데이터보다 싸게 같은 성능에 닿을까?
- Editor's Note로 분리 권장(T11 — 자사 연결 작위성 방지): 본문 마지막 문단에서 바로 "그러므로 페블러스"로 점프하지 말 것.
