# title-gate — 제목 게이트 (결정론 검사 + 눈감은 심판)

> 한 줄 비유: 형태 검사기는 자[尺]고, 심판은 제목만 보고 기사를 짐작하는 독자다. 자로 잰 뒤 독자에게 묻는다. 2026-09-30 부터 자에는 눈금이 하나 더 있다 — 사람들이 검색창에 치는 이름이 제목에 들었는가.

- 무엇: 발행 직전(`sns-write` 뒤, `manuscript` 앞) 이 run 이 만든 글의 제목 3슬롯(mainTitle·subtitle·pageTitle)을 결정론 검사기로 재고, ko 제목은 LLM 심판이 두 시험(중학생·클릭)을 매긴다. 핵심 검색어는 기획 단계에서 run 에 고정하고, 관문은 글의 기록과 제목을 그 값과 대조한다.
- 왜: 제목 정본 v2(2026-09-11) 아래서 발행된 10편 중 8편이 형님 판정에서 실패했는데, 결정론 검사기는 그 8편에 9~10점을 줬다. 형태 규칙은 필요조건일 뿐이다. 그리고 v3 아래서 제목을 쉽게 만드는 동안 새 글이 핵심 검색어(Jev·버니 샌더스·클라우데라)를 잃었다 — 형님 2026-09-28: "핫 키워드가 없는 제목을 누가 보겠니?" 정본(`docs/ko-style-standard.md` §4-2)의 핵심 검색어 규칙은 코드가, 두 시험은 읽는 쪽이 판정해야 한다.
- 효과: 제목마다 핵심 검색어 결함과 심판의 추측·점수·판정이 audit 에 남고, 미달 제목은 발행 전에 한 번 다시 지어진다. 기본은 발행을 막지 않는다 — 차단 스위치 `BLOG_TITLE_GATE_BLOCKING` 은 기본 끔이다(켤지는 형님 결정 대기).

## 1. 흐름

```
기획 단계(research·planning·storyline) ─▶ <runDir>/search-keyword.json ─▶ 엔진이 run 에 고정(state.searchKeyword)
  (발굴 후보에서 시작한 run 은 주제 줄 "핵심 검색어: …" 로 run 생성 때 고정)
        │
        ▼ title-gate
기획 고정값이 있고 새 ko 글에 메타가 없으면 엔진이 메타를 채운다
        ▼
결정론 검사(tools/title-census.py --check-html) — 옛 글 · 새 en 글(--require-keyword) · 새 ko 글(--require-keyword --pinned-keyword)
        │ 옛 글 위반 ─▶ audit 만(콘솔 후속, LLM 없음)
        │ 새 글 위반·핵심 검색어 결함·글 머리 결함 ─▶ sonnet 교정 1회(새 글만) ─▶ 검색어 메타가 바뀌었으면 되돌림 ─▶ 재검사
        │ 통과(또는 교정 뒤)
        ▼
눈감은 심판(ko 새 글만) 1단계:   mainTitle 만 → {guess, understand, natural}
                        클릭 단계: mainTitle + 핵심 검색어(인정 표기 포함) + 주제 첫 줄 → {expected_keyword, click}
                        2단계:   1단계 답 + subtitle + <main> 첫 <p> 둘 → {accurate, misleading, subtitle_understand}
        │ 임계 미달(understand<4 · click<4 · accurate<4 · subtitle_understand<4 · misleading)
        ▼
글쓰기 등급 모델(opus 계열)로 미달한 칸만 재작성 1회 ─▶ 통과했던 부제·검색어 메타는 원래 값으로 복원 ─▶ 결정론 검사 ─▶ 심판 한 번 더
        │
        ▼
관문 끝(finish): 남은 핵심 검색어 결함·권고를 audit 에 적는다 ─▶ 차단 스위치가 켜져 있고 결함·심판 미달이 남았으면 사람 검토로 멈춘다
                                                                 꺼져 있으면(기본) 발행 계속
```

> 심판 호출은 프롬프트를 **본문으로**(`inlinePrompt: true`) 넘긴다. 다른 단계처럼 `.current-prompt.md` 경로만 넘기면 Read 가 금지된 심판은 파일을 못 열고 "내용을 붙여 달라"고 되묻다 끝난다 — 2026-09-15 배포 뒤 09-18 까지 심판 12편이 전부 "1단계 JSON 파싱 불가"로 생략된 원인(2026-09-18 수리). `promptArgFor` 는 disallowedTools 에 Read 가 있으면 플래그와 무관하게 본문을 넘긴다.

| 구성요소 | 위치 |
|---|---|
| 단계 본체(교정·심판 호출·부제·검색어 메타 복원·차단 스위치) | `service/blog-service-engine/src/core/pipelines.ts` (`runTitleGate`, `titleGateBlocking`) |
| 핵심 검색어 고정(주제 줄·기획 파일 → `state.searchKeyword`) | `service/blog-service-engine/src/core/pipelines.ts` (`pinSearchKeyword`, `KEYWORD_PLAN_PHASE`) |
| 심판(프롬프트·파싱·판정·재작성 프롬프트·핵심 검색어 메타 읽기·채우기·복원·부제 복원) | `service/blog-service-engine/src/core/title-judge.ts` |
| 결정론 검사기(규칙의 단일 정본, TS 에 중복 구현하지 않는다) | `tools/title-census.py` |
| 규칙 본문 | `docs/ko-style-standard.md` §4-2 — 교정·재작성 프롬프트가 워커에게 먼저 Read 하게 한다 |

- 1단계는 **제목 한 줄만** 본다 — 핵심 검색어·주제 첫 줄·부제·본문을 보지 않는다. 발굴 run 의 주제 첫 줄은 "제목 방향: <발굴 제목>" 이라 최종 제목과 가깝고, 같은 호출에 넣으면 추측이 제목이 아니라 주제 줄에서 나온다. 그러면 2단계의 accurate(추측이 글과 맞는가)가 부풀어 오해·모호 검사가 약해진다(2026-09-30 리뷰). 핵심 검색어와 주제 첫 줄(run 주제의 첫 줄, 300자까지)은 **클릭 단계**에만 준다. 2단계는 1단계 답을 고치지 못하고 글과 대조만 한다.
- 심판 모델은 `MODEL_SONNET`, 재작성 모델은 `resolvePhaseExecution('title-gate', MODEL_OPUS)` — title-gate 는 `WRITING_PHASES` 밖이라 런의 fable 선택은 적용되지 않는다. `BLOG_MODEL_PHASE_TITLE_GATE` 로 덮어쓸 수 있다.
- en 파일은 결정론 검사만 받는다(핵심 검색어 검사 포함). 심판·재작성은 ko 파일만이다.
- 교정·핵심 검색어 결함·심판·재작성은 **이 run 이 새로 만든 글**(base 에 없던 파일)만 본다. 옛 글을 부수적으로 고친 run 이 검색어 기록이 없던 옛 글 때문에 결함·차단에 걸리거나 옛 제목(검색 결과 제목 포함)을 갈아 끼우지 않게 하려는 것이다. 옛 글의 위반은 `옛 글(base 에 있던 파일) 제목 위반 — 이 run 은 고치지 않는다, 콘솔 후속` 으로 audit 에만 남는다. 옛 작성 규칙과 옛 콘솔 캐스케이드가 쓰던 "<mainTitle> \| 페블러스" 검색 결과 제목은 새 규칙에서 결함이지만, run 이 본문 한 문장만 고쳤다고 LLM 이 그 검색 결과 제목을 갈아 끼우지 않는다(2026-09-30 리뷰 회귀).
- 재작성 상한은 1회다. 재작성 뒤 결정론 위반이 새로 생겨도 더 부르지 않고 audit 에만 남긴다.

## 2. 핵심 검색어 검사 (결정론, 2026-09-30)

핵심 검색어는 사람들이 이 이야기를 찾으려고 치는 이름이다(정의·표기는 `docs/ko-style-standard.md` §4-2). 이름 있는 제품·회사·사람·기관·법이 있으면 그 이름이고, 보통명사 한 낱말(AI·모델·회사·법안·연구소)은 핵심 검색어가 아니다. 인정 표기는 같은 이름의 다른 표기만이다. 검사기는 글 head 의 메타 두 줄을 읽는다(`</head>` 앞만 본다 — 본문의 예시 메타를 잡지 않는다).

```html
<meta name="pb-search-keyword" content="Jev">
<meta name="pb-search-keyword-forms" content="Jev|제브|TypeSafe Jev">
```

### 2-1. 기획 고정값 — 글이 스스로 적은 검색어만 믿지 않는다

글쓴이·교정·재작성이 검색어를 스스로 정하면, 이미 제목에 있는 말을 검색어로 적어 검사를 비켜 갈 수 있다. 형님이 버린 Jev 글 제목("말은 못 하고 고르기만 하는 AI, 정말 싸게 일할까?")에 검색어 `AI` 를 적거나 인정 표기 `Jev|고르기만 하는 AI` 를 적으면, 초판 검사기는 세 칸 모두 10점을 줬다(2026-09-30 리뷰). 그래서 검색어를 제목보다 먼저 정해 run 에 고정한다.

| 출처 | 언제 고정하나 |
|---|---|
| 주제 안의 `핵심 검색어: Jev \| 제브` 줄 — 발굴 후보의 `keyword`(발굴 프롬프트가 후보마다 적게 한다)를 콘솔·예약 발화가 주제에 넣는다. 운영자가 직접 적어도 된다 | run 을 만들 때(`setupPipelineRun`) |
| 기획 단계(blog `research` · report `planning` · dc-story `storyline`)가 쓴 `<runDir>/search-keyword.json` — `{"keyword": "Jev", "forms": ["Jev", "제브"], "basis": "…"}`. 기획 단계 프롬프트가 쓰라고 한다 | 다음 단계로 넘어갈 때(`executeNextPhase`). **write-ko 가 끝난 뒤에 적힌 파일은 읽지 않는다** — 제목을 지은 뒤의 검색어는 기획이 아니다 |

- 한 번 고정하면 바꾸지 않는다(audit kind `keyword-pinned`). 글쓰기 단계(write-ko·write-en) 프롬프트에 고정값을 적어 준다.
- title-gate 는 고정값이 있고 새 ko 글에 메타가 없으면 메타를 채운다(`핵심 검색어 메타 보충`). 새 ko 글은 검사기에 `--pinned-keyword` 로 고정값을 넘긴다 — 기록이 고정값과 겹치지 않으면 결함이고, 제목은 고정값으로 잰다. 고정값은 한국어 글의 검색어라 en 글에는 넘기지 않는다.
- **수리가 메타를 바꾸면 되돌린다.** 교정·재작성 프롬프트에 "pb-search-keyword·pb-search-keyword-forms 가 이미 있으면 바꾸지 않는다 — 검색어가 빠진 칸은 제목을 고쳐 넣는다" 를 적고, 수리 전후로 기록을 비교해 바뀌었으면 원래 태그로 되돌린다(`핵심 검색어 메타 복원`). 부제 복원과 같은 원리다. 수리 전에 기록이 없던 글은 새로 적는 것을 허용한다(그 값은 검사기가 이름인지 본다).
- 심판의 클릭 단계는 주제 첫 줄에서 사람들이 칠 이름을 스스로 짚는다(`expected_keyword`). 기록과 다르면 audit 에 남긴다(판정이 아니라 보고).

### 2-2. 라벨

칸 라벨:

| 라벨 | 슬롯 | 뜻 | 등급 |
|---|---|---|---|
| `핵심 검색어 없음` | mainTitle · pageTitle | 인정 표기가 하나도 들어 있지 않다 | 결함 (-3, 게이트 탈락) |
| `핵심 검색어가 뒤에 있음` | pageTitle | 브랜드 꼬리를 뗀 검색 결과 제목에서 첫 인정 표기가 앞 1/3(짧은 제목은 3자) 밖에서 시작한다 | 권고 (-1) — 아래 2-3 |
| `mainTitle와 동일(검색 변형 아님)` | pageTitle | 브랜드 꼬리를 뗀 검색 결과 제목이 본문 제목과 같다(띄어쓰기·문장부호·대소문자만 다른 것 포함) | 결함 (-3, 종전 권고 -2) |
| `브랜드 접미사 없음` | pageTitle | 끝이 ` \| 페블러스`·` \| Pebblous` 가 아니다 | 결함 (-3, 종전 권고 -1) |
| `pageTitle≠<title>` | pageTitle | config `pageTitle` 과 head 의 `<title>` 이 다르다(엔티티·JS 이스케이프·공백 차이는 같다고 본다). 검색 결과는 `<title>` 을 보인다 — 수리가 한쪽만 고치면 검사기는 통과를 주는데 검색 결과는 옛 제목이다 | 결함 (-3) |
| `전달문 종결(~라고 적는다)` | subtitle | 부제가 "~라고/~다고 적는다·적었다·적시한다·적혀 있다"로 끝난다 — 조문을 옮겨 적은 문장이라 무슨 일인지 말하지 않는다(2026-09-28 형님 판정, 샌더스 글 부제) | 위반 (-3) |

- config `pageTitle` 이 비면 `<title>` 을 검색 결과 제목 칸으로 잰다(칸의 `source: "title"`). 둘 다 없으면 칸이 없다.

글 머리 라벨(`keyword_labels`, 결함은 `keyword_defects` 에도) — 칸 밖에 두어 칸이 비어도 사라지지 않는다:

| 라벨 | 뜻 | 등급 |
|---|---|---|
| `핵심 검색어 미기재` | 메타(또는 `--keyword`)가 없다 | 새 글(`--require-keyword`)은 결함, 옛 글은 권고. 기획 고정값이 있으면 제목은 고정값으로 잰다 |
| `핵심 검색어가 이름이 아님(일반 낱말 "AI")` · `인정 표기가 이름이 아님(설명구 "고르기만 하는 AI")` | 보통명사 한 낱말(AI·모델·회사·법안·연구소·데이터 등)·설명구(관형형 "~하는"·조사 "~만·~보다"로 이어진 구)·수치만인 표기 | 결함 — 그 표기는 제목 대조에서 뺀다 |
| `핵심 검색어가 기획과 다름(기획 "Jev" · 기록 "AI")` | 기록의 어느 표기도 기획 고정값의 표기와 겹치지 않는다(같은 표기이거나 한쪽이 다른 쪽 안에 낱말로 들어 있으면 겹친다 — "샌더스"⊂"버니 샌더스") | 결함 — 제목은 고정값으로 잰다 |
| `기획 핵심 검색어가 이름이 아님("AI") — 기획 대조 생략` | 고정값 자체가 보통명사 | 권고 |

- 표기 비교는 대소문자·띄어쓰기·하이픈을 가리지 않는다("gemma 4" = "Gemma4"). 라틴·숫자로 시작·끝나는 표기는 앞뒤가 라틴·숫자에 붙어 있으면 다른 낱말로 본다("Jev" ≠ "Jevons", "GPT" ≠ "ChatGPT"). 한글 표기는 조사가 붙어도 인정한다("샌더스의").
- 앞 1/3 의 자는 `blog-search-appeal` 스킬의 검사와 같다(위치 ≤ max(3, 길이/3)) — 두 도구가 같은 제목에 다른 판정을 내지 않게.
- 핵심 검색어 자리 안의 숫자·약어는 이름의 일부라 수치·약어로 세지 않는다(Gemma 4 · ISO 5259-2 · CRISPR). **업계 용어는 검색어 안에 있어도 센다** — 검색어를 "AI 거버넌스" 로 적어 용어 규칙을 피하던 우회를 막는다.
- 미끼 규칙은 "N가지 비밀" 류만 잡는다 — "핵심 차이 5가지 비교"·"AI 품질 지표 15가지" 같은 정보성 개수는 미끼가 아니다.
- 메타 대신 핵심 검색어를 직접 주려면(옛 글 재현·단일 파일 검사): `python3 tools/title-census.py --check-html <파일> --keyword Jev --keyword-forms 'Jev|제브|TypeSafe Jev'`. 둘 중 하나라도 주면 메타 값은 통째로 무시한다. 엔진이 새 글에 붙이는 것: `--require-keyword`(기록 없음 = 결함) · `--pinned-keyword Jev --pinned-forms 'Jev|제브'`(기획 고정값). 결과 JSON 에 `keyword`·`keyword_forms`·`keyword_source`(`meta`|`cli`|null)·`keyword_match_forms`(제목 대조에 쓴 표기)·`keyword_labels`·`keyword_defects` 가 붙는다.
- 엔진은 라벨 문구만 읽는다 — 칸 라벨에 '검색어'가 든 것 = 핵심 검색어 라벨, 그중 '뒤에 있음' = 권고. 글 머리 판정은 `keyword_defects`(결함)와 나머지(권고)로 읽는다. 무엇이 결함인지는 검사기가 정한다 — 채점 규칙을 TS 에 두 벌 두지 않는다.

### 2-3. 검색어가 앞에 있어야 하나 — 판례집 C 와 규칙 교정 (2026-09-30)

검사기 초판은 검색 결과 제목이 핵심 검색어로 **시작하지 않으면**(앞 1/3 밖) 결함(-3)으로 봤다. 그러면 서치콘솔에서 잘 눌린 검색 결과 제목 일곱 가운데 둘이 게이트에서 떨어진다:

| 클릭률 | 검색 결과 제목 | 검색어 자리 |
|---|---|---|
| 6.1% (사이트 평균의 6배) | 스스로 연구하고 논문쓰는 AI — AI Scientist v2 분석 | 줄표 뒤(20번째 글자) |
| 3.0% | 한국 합성 페르소나 700만 — Nemotron-Personas-Korea 심층 분석 | 줄표 뒤(19번째 글자) |

판례집 원칙 "규칙이 판례와 어긋나면 규칙을 고친다"에 따라, 결함은 검색어가 **아예 없을 때만**이고 앞 1/3 밖은 권고 `핵심 검색어가 뒤에 있음`(-1)으로 내렸다. 판례집(`tools/title-gold-set.json`)의 C 일곱 행은 모두 게이트를 통과하고(C2·C7 은 권고 표시), 형님이 버린 검색 결과 제목(Jev·Gemma 4 덮어쓰기·샌더스)은 검색어가 아예 없어 여전히 결함이다. 권고는 교정·차단 사유가 아니다 — 교정 리포트에도 싣지 않는다.

## 3. 심판 (2026-09-30 개정)

- **세 호출**: 1단계(눈감음)는 mainTitle **만** 받아 `{guess, understand, natural}` 을 낸다. 클릭 단계는 mainTitle + 핵심 검색어(`pb-search-keyword`, 인정 표기 — 없으면 기획 고정값) + 주제 첫 줄을 받아 `{expected_keyword, click}` 을 낸다. 2단계는 1단계 답 + 부제 + 리드로 `{accurate, misleading, subtitle_understand}` 를 낸다. 1단계에 검색어·주제를 주지 않는 이유는 §1 에 적었다.
- **클릭 시험의 뜻**: 핵심 검색어를 검색했거나 뉴스에서 그 이름을 본 사람이 검색 결과·글 목록에서 이 제목을 보고 "그 이야기다" 알아보고 누르는가. 핵심 검색어(인정 표기 포함)가 제목에 없으면 click 3 이하. **주제 첫 줄이 고유명사(제품·모델·회사·사람·기관·법의 이름)를 부르는데 그 이름이 기록된 검색어에도 제목에도 없으면 click 3 이하** — 기록이 'AI' 같은 보통명사여서 제목에 들어 있어도 마찬가지다. 클릭 심판은 먼저 주제 첫 줄만 보고 검색어를 스스로 짚고(`expected_keyword`), 기록과 다르면 주제 쪽을 믿는다. 엔진은 짚은 이름이 기록과 다르면 `심판이 짚은 핵심 검색어 "…" ≠ 기록 …` 을 audit 에 남긴다.
- **이해 점수**: 낯선 이름(제품·모델·회사·사람·법)이 있어도 몇 낱말로 무엇인지 풀어 주었으면 깎지 않는다. 주인공을 보통명사로 뭉개 어떤 회사·어떤 법·어떤 AI 인지 모르게 했으면 understand 2 이하. 옛 지시("낯선 회사명 때문에 모르겠으면 낮게")는 지웠다.
- **부제 이해**: 부제만 읽은 중학생이 무슨 일인지 한 줄로 말할 수 있는가. 업계 용어를 풀지 않았거나, 문장이 부서졌거나, 숫자가 무엇의 수치인지 없으면 1~2. **조문·항목을 늘어놓아("~도 금지하고, ~하면 ~라고 적는다") 무슨 일이 있었는지 말하지 못하면 1~2** — 예: 샌더스 글 부제 "미국 상원에 나온 법안은 위험한 능력 여섯 가지도 금지하고, 능력이 사라졌는지 확인하지 못하면 30일 안에 없애라고 적는다" 는 1(형님 09-28 "무슨 글인지 모르겠다"). 검사기는 "~라고 적는다" 종결만 잡고, 세부 나열은 이 점수가 거른다.
- **채점 예**: 형님 판정만 쓴다 — 성공 1("AI는 생각의 도구일까, ‘인지 바이러스’일까?", 이름 붙은 주인공이 없는 개념 글) · 실패 5. 실패 가운데 셋이 핵심 검색어 누락이다: "말은 못 하고 고르기만 하는 AI, 정말 싸게 일할까?"(Jev 없음, 09-28) · "사람보다 똑똑한 AI를 금지하는 법안에 판정 기준이 없다"(버니 샌더스 없음, 09-28) · "데이터가 준비됐다는 회사의 대답, 믿어도 될까?"(어느 회사인지 없음 — 0점에 가깝다, 09-18). 1단계 채점 예는 까닭을 적을 때 이름(Jev·버니 샌더스·클라우데라)을 쓰지 않는다 — 1단계가 검색어를 보지 않게.
- **임계**: understand 4 · **click 4**(종전 3 — 검색어가 빠진 제목이 3 이하를 받으므로 임계 3 이면 그대로 통과한다) · accurate 4 · subtitle_understand 4 · misleading 이면 미달. natural 은 기록만 한다.
- **재작성 범위**: 미달한 칸만 다시 짓게 한다. 프롬프트에 현재 검색 결과 제목·핵심 검색어·기획 고정값·주제 첫 줄과 "고칠 칸 / 둘 칸"을 적고, 규칙 본문은 정본 §4-2 를 Read 하게 한다. 검색어 메타는 이미 있으면 바꾸지 않는다고 적는다.
- **통과한 부제 복원**: 첫 심판에서 subtitle_understand 가 임계를 넘었는데 재작성이 부제를 바꿨으면, 엔진이 원래 부제로 되돌린다. 프롬프트("통과한 칸은 건드리지 않는다")만 믿지 않고 코드로 지킨다. 핵심 검색어 메타도 같다(§2-1).

## 4. 비차단과 차단 스위치

기본은 발행을 막지 않는다. 심판 호출 실패·타임아웃(단계당 180초)·JSON 파싱 불가·mainTitle 없음은 `심판 생략 — <사유>` 로 audit 에 남기고 통과 처리한다. 재작성 호출이 실패하면 원제목으로 발행한다. 결과가 미달로 끝난 제목은 제목 검토 콘솔에서 사후 정리한다.

`BLOG_TITLE_GATE_BLOCKING=on` 일 때만, 관문 뒤에도 새 글에 핵심 검색어 결함(칸의 `핵심 검색어 없음`, 글 머리의 미기재·이름이 아님·기획과 다름)이나 심판 미달이 남은 run 을 `holdForPublish` 로 돌린다 — 발행을 버리지 않고 publish-prep 앞에서 사람 승인을 기다린다. 검사기가 크래시해 판정을 못 한 경우는 차단하지 않는다. 권고(`핵심 검색어가 뒤에 있음`)와 옛 글 위반으로는 차단하지 않는다. 새 글의 핵심 검색어 **미기재**는 이제 결함이다(종전 권고) — 기획 고정값이 있으면 엔진이 메타를 채우므로, 고정값도 없고 교정도 메타를 적지 못한 글만 남는다. 발행 차단으로 바꿀지는 형님 결정 대기라 기본은 끔이다.

## 6. audit 형식 (kind `title-gate`, phase `title-gate`)

한 제목당 한 줄, 사후 집계가 정규식으로 읽도록 형식을 고정했다.

```
<file>: 심판 통과 :: "<제목>" :: {"guess":"…","understand":5,"click":4,"natural":4,"accurate":5,"misleading":false,"subtitle_understand":4[,"expected_keyword":"…"]}
<file>: 심판 미달 :: "<제목>" :: {…} :: 미달 understand 2<4 (중학생 시험) · click 1<4 (클릭 시험)
심판 미달 → 제목 재작성 1회(<model>): <file>
통과한 부제 복원 — <file>: 재작성 부제 "<새 부제>" 대신 원래 부제 "<옛 부제>"
통과한 부제 복원 실패 — <file>: <사유>
<file>: 재작성 후 심판 통과 :: "<새 제목>" :: {…} (원제목 "<옛 제목>")
심판 생략 — <사유> :: "<제목>"
<file>: 심판이 짚은 핵심 검색어 "<클릭 단계가 주제 첫 줄에서 짚은 이름>" ≠ 기록 "<검색어>"(<표기|…>) — 확인 필요
핵심 검색어 메타 보충 — <file>: 기획 고정값 "<검색어>" (<표기|…>) — 글에 메타가 없었다
핵심 검색어 메타 복원 — <file>: <자동 교정|제목 재작성>가 "<바뀐 값>"(…) 로 바꾼 것을 원래 "<검색어>"(…) 로 되돌림
옛 글(base 에 있던 파일) 제목 위반 — 이 run 은 고치지 않는다, 콘솔 후속:
- <file>
    <슬롯>[<점수>] <라벨>: "<값>"
핵심 검색어 결함(결정론 검사):
- <file> <슬롯>: <라벨> "<값>"
- <file> 글 머리: <라벨> "<기록된 검색어>"
핵심 검색어 결함 잔존(차단 스위치 꺼짐 — 발행은 계속, 콘솔에서 사후 정리):
- <file> <슬롯>: <라벨> "<값>"
핵심 검색어 권고(차단 사유 아님):
- <file> pageTitle: 핵심 검색어가 뒤에 있음 "<값>"
관문 차단 — 사람 검토 대기 :: 핵심 검색어 결함 <N>건 · 심판 미달 <file>, …
```

결정론 검사의 audit(`§0 위반 감지 …`·`자동 교정 후 §0 재판정 통과`·`교정 후 위반 잔존`)은 종전 이름 그대로다 — `§0` 은 게이트 이름(호환)일 뿐, 규칙은 정본 §4-2 다. 이제 새 글만 싣는다. 위반 리포트(교정 프롬프트에도 그대로 들어간다)에 글 머리 결함이 있으면 그 줄과 함께 mainTitle·pageTitle 을 점수와 무관하게 싣고 고칠 방향을 붙인다 — 교정 프롬프트는 "리포트에 없는 칸은 건드리지 않는다" 라서, 칸이 빠지면 모델이 메타만 적고 제목에 이름을 넣지 못했다(2026-09-30 리뷰):

```
- <file>
    글 머리[핵심 검색어] 핵심 검색어 미기재: ""
    mainTitle[10] : "<값>" ← 메타를 적은 뒤 이 칸에 그 검색어가 없으면 고친다(주인공 이름을 넣는다)
    pageTitle[10] : "<값>" ← 메타를 적은 뒤 이 칸에 그 검색어가 없으면 고친다(주인공 이름을 넣는다)
```
