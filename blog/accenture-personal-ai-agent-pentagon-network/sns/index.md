미 국방부 전산망에서 두 달 동안 작동한 AI 코딩 에이전트가 회사 승인을 받은 도구가 아니었다는 보도가 나왔다. 액센츄어 소속 계약직 직원이 자기 개인 Claude Code 계정에 망을 연결해 뒀다고 WIRED가 익명 소식통 여럿을 인용해 10월 29일 전했다.

연결 대상은 여러 정보기관이 함께 쓰는 비분류망 NIPRNet의 운영 환경이었다. 업무를 자동화하려는 목적이었다고 한다. 에이전트에 코드 작성과 서버 구동을 맡기려면 먼저 시스템 안으로 들여보내야 했는데, 직원이 택한 방식은 자기 계정의 로그인 정보를 그대로 건네는 것이었다. 높은 신뢰 등급에 묶여 있던 관리자 권한이 에이전트에 함께 넘어갔다.

두 달이라는 시간은 보안 장비가 꺼져 있어서 생긴 것이 아니다. 에이전트가 사람의 자격증명으로 접속하면 기록에 찍히는 이름은 그 사람의 것이다. 로그를 읽는 쪽에는 권한 있는 직원이 유난히 일이 많았던 기간으로 보인다. 개인 계정이라 사용 내역도 회사 바깥에 쌓였고, 어느 승인 목록에도 없던 도구는 점검 대상에도 들어가지 않았다.

여기서부터는 주장이 엇갈린다. 보도는 직원의 로그인 정보와 비밀번호, NIPRNet 구조도가 외부 사이트로 빠져나간 정황을 전했다. 액센츄어는 철저하고 독립적인 조사 끝에 근거 없는 주장으로 확인됐다는 입장이다. 국방부는 자기 망이나 시스템 상태는 논평하지 않는다고만 답했다. 연방 계약업체에 걸린 72시간 사고 보고 의무를 지켰는지를 두고도 설명이 맞선다.

국방부라는 무대를 빼고 보면 구조 자체는 흔하다. 접근 권한을 가진 사람이 그 권한을 에이전트에 넘기고, 에이전트는 사람을 대신해 데이터까지 닿고, 그 작업은 사람 이름으로 남는다. 페블러스는 DataClinic으로 AI 학습 데이터의 품질을 정량 진단한다. 접근 경로를 표준화하는 일은 빠르게 진행되는데, 그 경로를 지나간 쪽이 사람인지 에이전트인지 갈라 적는 칸은 대개 비어 있다.

## LinkedIn (EN)

The AI coding agent that ran inside a Pentagon network for two months was not a company-approved tool. It was attached to an Accenture contractor's own personal Claude Code account, WIRED reported on October 29, citing multiple anonymous sources.

What was connected was the operating environment of NIPRNet, the unclassified Defense Department network shared by several intelligence agencies. The stated purpose was automation. For the agent to write code and spin up cloud servers it first had to get into the system, and the method the contractor chose was to hand over their own login credentials. Admin rights held at a high trust level passed to the agent along with them.

Two months went by, and not because the security tooling was switched off. When an agent signs in with a person's credentials, the access logs carry that person's name. To anyone reading them, a cleared employee simply looks busier than usual. Usage records for a personal account accumulate outside the company, and a tool that is on no approval list ends up on no review list either.

From there the accounts diverge. WIRED reported indications that the contractor's logins, passwords and a map of the NIPRNet environment were sent to an outside site. Accenture said the allegations were thoroughly and independently investigated and found to be without merit. The Defense Department said only that it does not comment on the status of its networks or systems. Whether the federal 72-hour cyber incident reporting duty was met is disputed by both sides.

Strip away the Pentagon setting and the shape is familiar. A person with access hands that access to an agent, the agent reaches the data on the person's behalf, and the work is logged under the person's name. ## Facebook (EN)

I have waited on an approval for a work tool and then, in the end, done the thing on my own account first.

A few days of work was not going to wait several weeks.

Reading the WIRED story last week brought that back.

An Accenture contractor connected NIPRNet, the Defense Department's unclassified network, to their own personal Claude Code account. For automation, as it was described.

The agent needed a way into the system, so they handed it their login credentials.

They were someone who held admin rights.

Two months passed that way.

What stayed with me is not what left the network. It is the two months.

Something holding admin rights was writing code and standing up servers without pause, and for two months nobody saw it.

Not because the security tooling was off.

When an agent signs in with a person's credentials, what the record keeps is the person's name.

A borrowed name, if it needs a term.

To whoever reads the logs, a cleared employee is simply having an unusually productive stretch. Nothing in the record separates what the person did from what the agent did.

"Whose name is the agent inside our data using right now?"
