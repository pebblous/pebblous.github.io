Executive Summary

OpenAI has proposed that AI developers draw a shared safety line and write it as a single number called perplexity. In a post published on November 22, chief scientist Jakub Pachocki argued that the log-perplexity a model reaches in pretraining should become an industry-wide metric, and that until people can tell what an AI is doing and keep watch on it well enough to clear a milestone set in advance, no company should drop below a line the industry draws together. The internal numbers he published alongside it: GPT-3.5 at roughly 0.99, GPT-4 at roughly 0.91, recent models below 0.8.

The part worth looking at is not the numbers but the footnote attached to them. The evaluation data that produced these values has been, ever since GPT-3.5, a fixed snapshot taken from OpenAI's own codebase. And the admission that developers use different evaluation data and different training mixtures, so the numbers do not compare cleanly between companies, is not a critic's objection. Pachocki wrote it into the same post. It is a line everyone is asked to hold, and right now one company can compute where it sits.

That structure showed itself the next day. Microsoft placed its own foundation model, MAI-2 Base, on the same scale at 0.819, which it could do only because OpenAI opened its own test set to that one partner. That second number showed, before anything else, which door a shared standard still has to pass through.

Sections 1 through 3 set out what the post says and how the industry answered. Section 4, which holds that an open test set is a precondition for any shared norm, is this article's own reading.

1

Pachocki Reports the Numbers and Proposes Where to Stop

Perplexity measures how confused a model is about the character coming next. You show the model a body of data it did not train on, and you average how well it predicts each following token. A smaller value means less confusion, so lower is better. Pachocki reported the logarithm of that value, log-perplexity, which is equivalent to cross-entropy loss. That is why the numbers in the post move in the second decimal place. Undo the logarithm and the span each of those steps covers is far wider.

What he released is the record OpenAI has kept of this value across model generations. GPT-3.5, the model behind the first ChatGPT, sat at roughly 0.99. At that level models became able to hold a fluent conversation. GPT-4 was roughly 0.91, and around then models began to get real work out of chain-of-thought, the intermediate reasoning steps they write before answering. Recent models have come down below 0.8 and started turning out results in cybersecurity and mathematics unlike anything before. Pachocki wrote that after switching to a model with log-perplexity around 0.76, it began producing results on math problems that had stayed open for a long time.

Pachocki then takes a further step. Once models enter the band between 0.68 and 0.7, he wrote, we should expect another round of transformative capability. On top of that forecast he laid the proposal: that developers accept perplexity as a common metric, and that nobody go below a jointly agreed line until our ability to understand and monitor AI behavior reaches a concrete milestone. The example he gave of such a milestone was successor techniques to the methods that let researchers inspect a model's chain of thought.

Pachocki is equally clear about what the metric cannot see. Chain-of-thought reasoning does not reduce the perplexity a model achieves. Reinforcement learning and tool use bolted on after pretraining can lift real capability a long way while this number barely moves. That is why GPT-4.1 and o3 land in effectively the same spot on the post's graph. How far the value can fall is also unknown, because, as the post puts it, we do not know what the inherent entropy of the data is.

The Test Set Behind Those Numbers Sits Inside OpenAI

A perplexity value is not decided by the model alone. Change the data the model is tested on and the same model gets a different number. Test it on code and a model strong at code does well; test it on fiction and the result moves. So the first question to ask of this value is not about the model but about what it was tested on.

A footnote gives the answer.

"sourced from our internal codebase, and those are the numbers reported here (for a fixed snapshot)"

Which means every figure since GPT-3.5 came off one single body of data. The post calls that data a held-out dataset, kept out of training, and it gives GPT-3.5's 0.99 as a value on the current main evaluation dataset. Even the scores of older generations, in other words, were placed on the test set in use today. Freezing it as a fixed snapshot is the right call for comparing across time, because a moving target makes the trend line meaningless. The problem is that the snapshot is one company's private source code. Nobody outside that company can measure another model on the same data.

The same cluster of footnotes also shows that the metric was never designed to be published. In the GPT-2 and GPT-3 generations, performance at predicting code was a poor proxy for general capabilities. This is a tool that was used internally for tracking and became useful at some generation along the way, not a ruler built from the start for the industry to share.

Nor was the limit on comparability first raised by a critic. It is in the body of the post.

"Different developers use different evaluation datasets and train on different data mixtures."

Put the two sentences side by side and the shape of the proposal appears. It asks everyone to hold one line, while conceding in the same post that each company holds its own ruler and the rulers are marked differently. So when another company announces "we are at 0.82," the first thing to work out is whether that value means what OpenAI's 0.82 means. The day after the post went up, that happened.

3

The Industry Read the Same Post Two Opposite Ways

Within a day the response had split in two. Sam Altman called it the most important thing OpenAI has published in a while, and Mustafa Suleyman, who runs Microsoft AI, called it super important and gave the credit to Pachocki and OpenAI. The case for the praise is that it is rare for a company to publish its whole internal tracking curve and then argue for slowing itself down.

Suleyman's support came with a number attached. Writing the day after the post, he said, "We fully support OpenAI's transparency initiative," and disclosed that Microsoft's own foundation model MAI-2 Base has a log-perplexity of 0.819, "putting it in the same ballpark as the GPT-5.6 Sol base model." The value comes from a run on OpenAI's evaluation dataset, and he noted that "Our model uses the same tokenizer as OpenAI, so the numbers are directly comparable." In the same message he wrote that "the fact we have access to OpenAI's evaluation dataset is a special case," and added that "we might need to report bits-per-byte (BPB) rather than perplexity since different labs use different tokenizers." The chart he posted also marked the previous generation, MAI-1 Base, at 0.878.

The other side drew a different conclusion from the same facts. The critical outlet traictory wrote that what OpenAI released is a metric nobody outside the reporting lab can compute, and called the post a press release with decimals. A Hacker News comment the outlet cited compresses the problem. A reader took a perplexity of 5.7 reported for some public model and converted it with a base-10 logarithm to get 0.756, a hair away from the 0.76 that marks the math breakthrough on OpenAI's chart. But that 5.7 came off a body of text the reader had chosen, so traictory's verdict read: "The arithmetic is right and the comparison is meaningless, which is what “different evaluation datasets” means in practice."

A second criticism is that there is little policy here yet. The passage proposing common limits is a single paragraph near the end of the post, and it holds more than the limit itself. The post asks developers to establish shared norms for how models are evaluated and for pre-deployment red-team safety checks, to align on transparency standards, and it frames the limit less as one line drawn once than as a series of successive thresholds used to pace development. What is missing comes after that. What the first threshold would be, who checks that it is held, who certifies that a milestone has been reached, and what follows for a company that crosses it are all absent. The same outlet summed the post up as fair for forecasting and weak for regulation, and offered two real tests: whether another lab publishes its own curve on a public fixed corpus, and whether the common limit ever acquires an actual number and an outside auditor.

The first test got an answer within a day, and the answer was half of one. A second number did appear, but the conditions that let it sit on the same scale as OpenAI's were two: OpenAI opened its private test paper to a particular counterpart, and that counterpart happened to use the same tokenizer. No public fixed corpus made it possible. Suleyman himself called the route a special case and had to propose, in the same breath, an alternative for labs whose tokenizers do not line up. The second test, an actual number and an outside auditor, is still unanswered.

There is tension in the condition for crossing the line as well. Crossing is premised on successor techniques to chain-of-thought monitoring, yet the monitorability study OpenAI released on November 10 found that such monitoring tends to weaken across a model's lifecycle. The safety valve ends up tied to a tool that is getting worse.

The timing is worth reading too. Pachocki warned that AI may be able to accelerate its own development as early as 2027, and that this pace could outrun progress in how well people can follow and police what models do. A footnote in the post singles out the steepening of the loss curve during 2026. Most of that acceleration, it says, came from long-running research and compute investment and the contribution from automation is still small, though it attaches the observation that recent models have begun making meaningful contributions to AI design. In the United States, congressional discussion of AI safety rules is moving again after the midterms, and some senators are talking about setting up a committee dedicated to AI policy. President Trump has opposed broad limits on AI development, which leaves room for friction with the new Congress. This is a moment in which a ruler the industry produced first could be picked up by a regulatory debate as it stands.

4

Why Pebblous Is Watching This

To anyone working on data quality the shape is familiar. Whether a metric can be trusted is usually decided not by what is being measured but by the data used to measure it. The contamination problem that keeps recurring in model benchmarks worked that way. Let test questions leak into training data and the score rises while the ability the score pointed at stays where it was. An evaluation whose held-out set is never published is the same case. Nobody but the organizer can re-score under the same conditions. The data behind these numbers is, by its own name, a held-out set.

This proposal moves that structure into the seat of a safety norm. A wrong benchmark score shakes a marketing line and stops there. A line that says "this far and no further" is different. Where that line sits decides which models get built bigger and when to stop. If only one company can compute the number in that seat, operational control of the norm follows the number.

None of which is a reason to fault the choice of perplexity. Treating pretraining capability as one continuous value and comparing generations along it is a useful idea, and publishing an internal curve is not common in this industry. But for the word "common" to hold, three things beyond the name of the metric have to be shared.

  • The same test paper. A fixed evaluation corpus anyone can download and run is what puts each company's value on one scale. Today each company measures on its own data and calls the result by the same name. Even the data Microsoft used for the second number belonged to OpenAI.
  • The same measurement procedure. A small difference in tokenization, document length or deduplication rules moves the second decimal place easily. If a limit is going to be argued over in units of 0.01, procedure matters as much as the value. That Suleyman led with the fact that his model shares OpenAI's tokenizer, and raised bits-per-byte as an alternative, is a sign the industry already senses this condition.
  • The right to recompute. An outside auditor has to be able to reproduce the figure with the same data and the same procedure. Without a path to reproduction the number is less a standard than a disclosure. Where that right currently sits is answered by how 0.819 became possible.

All three are questions about how data is prepared and published, not about models. Read AI-Ready Data narrowly, as data whose values are clean, and this territory stays invisible. A number becomes a shared standard only when it carries what it was measured on, who holds that data, and whether anyone else can reproduce the conditions. Evaluation data is where that demand bites hardest.

So the question to put to this post is not whether 0.76 is the right number. It is whether our industry is ready to accept, as a norm, a number measured on somebody's data. Pachocki's post did not dodge that question; it wrote it into a footnote and then made the proposal, leaving the answering to everyone else.
