Executive Summary

A method posted to arXiv finds wrong labels in a training set, and estimates how many there are, using nothing but one trained classifier. The paper by Yuchen Li and four co-authors, "Find, Count and Fix Wrong Labels from a Trained Model, without Clean Labels or Shared Data" (submitted November 17, 2026, revised November 21), checks which parameters each example's gradient leans toward and compares that with the average of examples carrying the same label. The authors say the method needs no clean reference set, no held-out validation set and no retraining.

Label noise gets hard to detect once a model has memorized the wrong labels. According to the paper, after the model fits 99–100% of its wrong labels, scores that rank examples by loss or gradient size fall to an AUC of 0.73–0.76 on the human-labeled CIFAR-10N set. Gradient allocation held at 0.94–0.96 under the same conditions. Retraining without the flagged examples raised test accuracy in all 22 image noise settings.

It does not clearly beat the existing method. Against confident learning in 11 settings, the difference in detection AUC was not statistically significant, and confident learning came closer to the true wrong-label rate. The advantage is that the computation ends with reading a single final model. Pebblous sees the method as a candidate for putting a number on "data label accuracy" (Acc-ML-7), a measure under the accuracy characteristic of ISO/IEC 5259-2, without an answer key. The paper does not mention any ISO standard; this mapping is Pebblous's interpretation.

On CIFAR-10N's Worst Labels, Loss Scores Fail Once the Model Memorizes

Label noise means the answer attached to a training example is wrong, as when a photo of a cat carries the label "dog." The paper relies mainly on CIFAR-10N, a public dataset that collects labels human annotators re-assigned to the 50,000 CIFAR-10 images. Its "worst" version picks a wrong annotator label whenever one exists, so it has the most errors. By the paper's count, 9.0% of labels are wrong in the majority-vote version (aggregate), 17.2% in the single-annotator version (random-1) and 40.2% in the worst version. Because these are mistakes real people made, they are harder to find than synthetic noise created by shuffling labels at random.

The usual approach looks for examples the model finds unusually hard. Examples with high loss, large gradients or high self-influence are put forward as wrong-label candidates. The trouble is that with long enough training the model fits the wrong labels too. The models in the authors' experiments reproduced 99–100% of the wrong labels on the training data. At that point a wrong example's loss is small as well and no longer stands apart from correct ones.

The paper's results on CIFAR-10N's worst labels are below. AUC is the probability that, given one randomly drawn wrong label and one correct label, the score ranks the wrong one higher. A value of 1 separates them perfectly; 0.5 is a coin toss.

Score What it looks at AUC on a model that memorized the labels
Loss · gradient norm · self-influence How hard the model finds the example 0.73–0.76
Feature-space margin How close the internal representation sits to another class 0.79–0.84
Gradient allocation (proposed) Which parameters the gradient concentrates on 0.94–0.96

The gap is wider when it comes to counting. Estimating the wrong-label rate from the model's predictions or feature margins captured only 0–6% of the true rate on a model that had memorized the labels, the paper reports. Even if four images in ten are mislabeled, the estimate comes out close to "nearly clean." In a data quality audit, that is the most dangerous kind of error.

2

Gradient Allocation Drops Magnitude and Compares Direction With the Class Average

The authors monitor the output projection layers of the last four backbone blocks: the attention and MLP output projections in ViT-S, and the MLP output projections in ConvNeXt-T. For one example and its label, they compute the gradient at these layers and divide the absolute values by their total. Magnitude disappears, and what remains is the proportion of change the model wants to make in each parameter. The paper calls this the allocation.

The decision takes four steps.

  1. Average the allocations of examples sharing a label to build a reference allocation for each class.
  2. Take how closely the example's allocation matches its own label's reference (cosine similarity) and subtract its similarity to the closest other class. This is the margin.
  3. Switch the label to the closest other class and repeat the calculation.
  4. If the switched label's margin is larger than the original label's, flag the example as mislabeled.

The rule has no threshold for anyone to set. It compares two numbers within one example, so there is no baseline to recalibrate for each dataset. The share of flagged examples is the estimate of the wrong-label rate. The number flagged equals "true wrong labels × recall ÷ precision," so when recall is lower than precision the estimate falls below the true rate. On that basis the paper advises reading the estimate as a lower bound.

The authors explain why magnitude is discarded. When a model memorizes a wrong label, the loss and gradient size for that example shrink, but the mix of parameters the remaining gradient points to stays different from that of correctly labeled examples in the same class. This is the authors' account of the mechanism; Pebblous has not reproduced it.

The choice of four blocks came from experiments. On CIFAR-10N's worst labels after memorization, watching only the last block gave ViT-S an AUC of 0.919, and watching four blocks raised it to 0.965. ConvNeXt-T went from 0.877 to 0.954. Using the cheaper classifier head alone dropped the AUC to 0.654 and read just 4% of the true wrong-label rate. The authors' interpretation is that the final features are what gets rewritten most late in training, so the signal survives in the blocks before them.

3

Wrong-Label Rates on CIFAR-10 and Food-101N, a Lower Bound for Human Labels

The experiments cover 22 image settings and 9 text settings. On the image side they combine human labels (CIFAR-10N, CIFAR-100N, CIFAR-10H), web-collected labels (Food-101N) and injected synthetic noise (symmetric and asymmetric noise on CIFAR-10 and CIFAR-100, and 40% symmetric noise on Food-101). The models are ViT-S/16 and ConvNeXt-T, both pretrained on ImageNet. On the text side, NoisyAG-News, which carries human labeling errors, and GLUE's SST-2, QQP and MNLI with injected noise were tested on RoBERTa-base, DeBERTa-v3-base and Qwen3-1.7B-Base.

On CIFAR-10 the method captured 54–96% of the true wrong-label rate using a model that had memorized the labels. Estimates based on prediction and feature margins reached only 0–6% on the same models. Results vary widely by noise type. On human CIFAR-10 labels it read 43–73% of the true rate, and on the web-labeled Food-101N, where the true rate is 19.2%, ViT-S read 13.1% and ConvNeXt-T 9.3%. The more human the errors, the further the estimate falls below the real figure.

Some errors are a clear weak spot. On CIFAR-100, it found only 28% of wrong labels that stay inside the same superclass (for example, one kind of tree mislabeled as another in the "trees" group), against 54% of errors that cross superclasses. Similar classes produce similar gradient allocations, so they do not separate well. On text, RoBERTa failed to memorize the wrong labels at all in three of five QQP runs. That breaks the method's premise of a model that has memorized the wrong answers, and the authors say estimates in that setting should be read only as lower bounds.

The method also proposes corrections. The other class that produces the larger margin is the suggested fix. In noise settings where the true label is known, the suggestion matched the true label 39–93% of the time, with a median of 73%. That is better suited to ordering a list for human review than to automatic relabeling.

4

Retraining Without Flagged Examples Lifts CIFAR-10 Accuracy From 48.1% to 94.7%

The downstream question is whether removing the flagged labels actually makes the model better. The authors removed the flagged examples from the training data and retrained from scratch. Test accuracy rose in all 22 image noise settings, by 11.6 points on average. The largest change came on CIFAR-10 with 60% symmetric noise, where ViT-S went from 48.1% to 94.7% test accuracy. Across models in that same 60% setting, the gain ranged from 28 to 47 points.

The paper includes a control. Removing the same number of examples at random and retraining changed accuracy by only −1.7 to +1.8 points, evidence that the gain comes from removing wrong labels rather than from having less data. Applied to data with clean labels, the procedure changed accuracy by at most 0.13 points. No side effect of cutting large numbers of good examples from clean data was observed.

The authors also compared what to remove. Across 11 noisy ViT-S settings, removing the examples flagged by gradient allocation gave a mean test accuracy of 90.2% after retraining. Removing the same number of highest-loss examples gave 85.8%, and removing the examples confident learning found gave 90.3%. Gradient allocation tied confident learning, but confident learning deleted 1.0–2.8 times as many examples and needed four extra training runs. Among deleted examples, the share that were truly mislabeled averaged 93.7% for gradient allocation, the highest, against 84.6% for confident learning and 75.3% for the loss criterion.

The retraining evidence covers images only. The authors did not retrain after cleaning text data and leave that as a next step. Anyone applying the method straight to text label cleanup should account for that gap.

5

Confident Learning Across 11 Settings: No Significant Difference in AUC

Confident learning picks out wrong labels by checking a model's predicted probabilities against the observed labels, and it is widely used through the open-source library cleanlab. To get fair predictions it relies on cross-training, splitting the data and training the model several times. The authors ran both methods side by side on 11 noisy settings.

Measure Confident learning Gradient allocation Verdict
Detection AUC (mean) 0.969 0.958 Not significant (Wilcoxon test, p=0.21)
Precision 0.85 0.94 Gradient allocation ahead in all 11 settings (p=9.8×10⁻⁴)
Wrong-label rate estimate (vs. true) 93% 74% Confident learning closer to true
Compute (5,000 images, ViT-S) About 23 GPU-minutes of extra training 14 seconds Gradient allocation reads only the final model

In short, detection is a draw, precision goes to gradient allocation and rate estimation goes to confident learning. Gradient allocation's flags are more likely to be truly wrong, but it flags fewer, so it reads the rate low. The authors' case rests on cost and requirements. Confident learning needs enough access to the data to retrain the model; gradient allocation needs only one already-trained model and per-example gradients.

That is also where the practical choice divides. With time to retrain, access to the data and a need for the rate itself to be accurate, confident learning is the better tool. When all that is available is a finished model, or the data cannot be moved, gradient allocation is an option that still works.

6

Split Audit Sends 2K+4 Numbers per Example Instead of the Data

The "without Shared Data" in the paper's title refers to a split audit setup. The data owner runs the model on its own machine, computes a set of numbers for each example and sends them to the auditor. Each example takes 2K+4 numbers, where K is the number of classes, so a 10-class task sends 24 numbers per example. Without seeing any image or text, the auditor reproduces the same flags and the same rate estimate from those numbers alone.

To check whether the numbers leak the originals, the authors ran a gradient inversion attack themselves. The reconstructed images scored a PSNR of 12.4 dB against the originals, no closer than the class's average image (12.6 dB). Among 1,000 candidates, the image nearest to a reconstruction was the actual original in 0.67% of cases. The result shows one attack being resisted; it is not a mathematically guaranteed protection like differential privacy.

Speed suits audit work. Auditing 5,000 images took 14–27 seconds on a single NVIDIA RTX 4090. Because the model is not retrained, the cost of an audit is close to the time the data owner spends passing the data through the model once.

By the paper's cost table, that is about one-hundredth of the time it took to train the model for 40 epochs (27–33 minutes for ViT-S, 51–68 minutes for ConvNeXt-T). Audit time grows with the number of examples; covering all 50,000 took 146 seconds on ViT-S and 272 seconds on ConvNeXt-T. Sometimes the full set is unnecessary. On CIFAR-10N, auditing just 500 images gave the same AUC as all 50,000. On the 100-class CIFAR-100N, 500 was not enough; it took 5,000, about 50 per class, to bring the AUC within 0.01 of the full-set value. There have to be enough examples to build each class average.

7

ISO/IEC 5259-2 Data Label Accuracy (Acc-ML-7) and DataClinic Audits

ISO/IEC 5259-2, the international standard for AI training-data quality, sets seven measures under its accuracy characteristic. One of them, Acc-ML-7 "data label accuracy," measures whether labels are accurately assigned to each element in the dataset (ISO 5259-2 data quality cheat sheet). The standard defines what to measure; it does not say how to obtain that value for data whose correct answers are unknown.

Pebblous sees this paper as one candidate for filling that gap. The following three points are Pebblous's interpretation and do not appear in the paper. First, the wrong-label rate estimate can be reported as a lower bound on Acc-ML-7. Second, the high-precision flag list can set the order in which people re-check labels. Third, the split audit opens a way to answer "so what share of our data is mislabeled?" with a number in audit contracts where customer data cannot leave the premises.

DataClinic's ImageNet audit examined the data distribution and image features directly to find label noise and duplicates. Gradient allocation examines the trained model instead of the data, so the two audits produce different evidence. That examples flagged by both on the same data can be treated as likely mislabeled is also Pebblous's judgment.

The paper is clear about its limits. Only two image backbones and three text models were tested. On human and web errors the estimate runs below the true rate, and confusion between similar classes is hard to catch. If the premise that the model memorized the wrong labels fails, the method does not hold. The authors list as next steps attaching formal guarantees such as differential privacy to the shared numbers, and auditing the labels of several data owners at once, as in federated learning. An audit report that uses this number should state it as a lower bound: at least this much is wrong.
