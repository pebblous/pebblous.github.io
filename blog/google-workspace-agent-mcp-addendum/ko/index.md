# 구글 워크스페이스, AI 에이전트 전용 통로 의무화… 학습 금지

_2027년 2월부터 AI 에이전트는 전용 통로로만 워크스페이스 데이터에 닿고, 모델 학습에 쓰는 일은 금지된다_

## Executive Summary

> [!callout]
> 구글이 워크스페이스 데이터에 닿는 AI 에이전트를 사람이 쓰는 앱과 갈라 놓았다. 2026년 11월 25일 정식 공개한 워크스페이스 MCP 서버와 명령줄 도구(CLI)가 에이전트에게 열어 둔 유일한 문이고, 같은 날 붙인 「Workspace AI Tools Addendum」은 그 문으로 건너간 데이터를 어디까지 쓸 수 있는지 적은 약관이다. 사람이 손으로 쓰는 일반 앱은 지금까지처럼 REST API를 쓴다. 자리가 바뀌는 쪽은 에이전트다.

> 바꿀 시한도 함께 나왔다. 2027년 2월 1일부터 기술적으로 강제하고, 4월 1일부터 사용량 등급에 과금을 시작한다. 약관이 거는 조건은 통로보다 쓰임새에 몰려 있다. 워크스페이스 데이터와 거기서 뽑아낸 것으로 모델을 학습시키거나 미세조정하지 못하고, 뽑아낸 것은 30일 넘게 보관하지 못하며, API를 긁어 가는 것도 막혔다. 연결을 끊고 나면 그동안 모아 둔 것도 지워야 한다.

> 1절부터 4절까지는 구글 워크스페이스 공식 발표와 구글 클라우드 블로그, 워크스페이스 업데이트 공지, 그리고 약관 전문에서 확인한 사실이다. 4절이 옮긴 조항의 구분과 문구는 약관 본문과 직접 대조했다. 이 변화를 사람 계정을 빌려 쓰던 접근이 에이전트 신원으로 갈라지는 흐름으로 읽은 5절은 이 글의 해석이다.

## 에이전트가 들어올 문이 따로 생겼다

구글은 11월 25일 워크스페이스 MCP 서버와 워크스페이스 CLI를 정식 버전으로 내놨다. MCP 서버는 지메일과 드라이브, 문서, 시트, 슬라이드, 캘린더, 챗, 태스크 여덟 가지를 연결하고 킵은 곧 붙는다. CLI는 노트북이나 서버에서 도는 에이전트, 터미널에서 돌리는 자동화 작업을 위한 쪽이다. 결과를 구조화된 JSON으로 내주고, 로그인할 때 받는 권한 범위를 좁혀 둔다.

발표문이 같은 자리에 적어 둔 약관이 「Workspace AI Tools Addendum」이다. AI 에이전트가 워크스페이스 데이터에 닿으려면 기존 REST API를 직접 부르지 말고 MCP 서버나 CLI를 거치라고 요구한다. 이 요구는 모든 소프트웨어가 아니라 에이전트에게 걸린다. 사람이 화면을 보며 쓰는 일반 앱은 지금 쓰는 API를 그대로 쓴다.

둘을 가르는 표시도 생겼다. 구글 클라우드 콘솔의 OAuth 2.0 클라이언트 설정에 "이 클라이언트를 AI 기반 에이전트에 사용함"이라는 체크 상자가 붙었고, 설정값으로는 is_agentic이라는 이름으로 남는다. 에이전트가 아닌 기능은 별도의 클라이언트를 쓰라는 안내가 함께 붙었다. MCP 서버는 에이전트용으로 표시되지 않은 클라이언트의 접속을 거절하고, 구글 클라우드의 프롬프트 주입 검사 서비스인 Model Armor와 맞물린다. 같은 회사가 에이전트와 일반 앱을 함께 운영한다면 자격 하나로 둘을 같이 돌리던 구성부터 손봐야 한다.

## 토큰 하나를 '사용자의 의도'로 읽던 전제

왜 통로를 따로 내는지는 구글 클라우드 블로그가 한 문단으로 적었다. 워크스페이스 엔지니어링 담당 찬두 소타 부사장과 구글 클라우드 플랫폼·SRE 부문 브래드 캘더 사장이 함께 쓴 글이다.

기존 REST API는 사람의 속도로 움직이는 앱을 위해 만들어졌고, 거기서는 유효한 OAuth 토큰이 곧 사용자의 의도를 뜻했다. AI 에이전트가 정보를 읽는 데서 나아가 메일과 문서, 데이터셋, 클라우드 인프라를 넘나들며 기계의 속도로 스스로 행동하게 되면서, 유효한 토큰 하나로는 더 이상 충분하지 않게 됐다. 정책 검사와 데이터 경계, 사람의 확인이 요청 경로 안에 들어와 있어야 한다.

원문: "Traditional REST APIs were built for human-paced apps where a valid OAuth token implied user intent. … Policy checks, data boundaries, and human confirmation have to live in the request path." 우리말로 옮긴 것은 페블러스다.

문장 안에 전제 하나와 그 전제가 깨지는 지점이 같이 들어 있다. 전제는 토큰을 건넨 사람이 지금 그 일을 원하고 있다는 가정이다. 사람이 버튼을 누를 때마다 요청이 하나씩 나가던 시절에는 그 가정이 거의 맞았다. 에이전트는 사람이 한 번 승인한 자격으로 한참 뒤까지, 사람이 따라 읽을 수 없는 속도로 요청을 낸다. 토큰은 여전히 유효하지만, 그 요청까지 사람이 원했는지는 토큰만 봐서 알 수 없다.

그 전제가 얹혀 있는 규모도 같은 글에 숫자로 적혀 있다. 워크스페이스 API는 한 달에 2조 8천억 번 넘게 호출된다. 공개된 드라이브 API 트래픽만 2022년의 두 배 반이 넘고, 드라이브에서 하루에 일어나는 읽기 180억 건 이상이 사람의 화면이 아니라 API를 부르는 쪽에서 온다. 토큰 하나를 사람의 뜻으로 읽는 규칙은 이 숫자 전부에 같이 걸려 있다.

그래서 구글이 고른 답은 확인을 요청 경로 안으로 옮기는 쪽이다. 아래 그림의 위쪽이 지금까지의 경로이고, 아래쪽이 2027년 2월부터 에이전트가 써야 할 경로다.
